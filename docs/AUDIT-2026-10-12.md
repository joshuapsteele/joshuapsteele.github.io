# Repository audit — 2026-10-12

Dated snapshot of joshuapsteele.com. Do not update this report as fixes land; use [CLEANUP-CHECKLIST.md](CLEANUP-CHECKLIST.md).

## Assessment

The site builds quickly and the earlier metadata cleanup has held up. The best next investment is improving rendered-site validation and removing redundant browser work, followed by making deployment safer. A framework migration or wholesale reorganization is not warranted by these findings.

This was a local source and production-output audit, not a live-site performance benchmark or exhaustive external-link crawl. No content, templates, deployment configuration, media, or old reports were changed. External-link results from May remain historical evidence, not a current health check.

- Hugo reports 819 pages, 69 paginator pages, 212 aliases, and 177 static files.
- Amazon disclosure check: passes for 110 pages / 530 affiliate links.

## 1. High: make published output authoritative for link validation

`scripts/check-internal-links.py` first checks `public/`, but then accepts a link if a similarly named Markdown source exists (around lines 288–311). This allows links to drafts and links that ignore a post's explicit `url:` to pass. It also scans content rather than navigation/template output.

An independent HTMLParser scan of production HTML found **9 broken anchor occurrences across 7 distinct paths**, treating trailing-slash variants as the same destination:

| Source | Broken destination | Recommended resolution |
| --- | --- | --- |
| Homepage “Why” button; `/slashes/` | `/why/` or `/why` | `content/pages/why.md` is a draft. Remove public links until it is ready, or deliberately publish it. |
| `/slashes/` | `/sale`, `/tip` | Draft links are still clickable despite strikethrough. Render plain text until published. |
| `/slashes/` | `/subscriptions` | Remove the link or supply a published destination. |
| Both regional ETS paper/presentation posts | `/blog/reconciliation-and-the-lack-thereof-atonement-ecclesiology-and-the-unity-of-god/` | Use `/reconciliation-and-the-lack-thereof-atonement-ecclesiology-and-the-unity-of-god/`. |
| `/testimony-brief/` | `/a-crucicentric-credo/` | Use `/theology-outline/`; consider preserving the older URL as an alias if it was public. |
| `/tidbits-2025-09-26/` | `/blog/tidbits-2025-09-19` | Use `/tidbits-2025-09-19/`. |

When `public/` is available, do not fall back to source existence. Add a rendered-output check covering navigation, shortcodes, links, and media; return a nonzero exit status on confirmed failures and run it in CI. Include focused cases for drafts and explicit URL overrides. The supplementary scan checked local anchor and selected media/script destinations, not fragments, CSS URLs, or srcset.

## 2. High: fix double-encoded URLs in inline JavaScript

`layouts/partials/webmention_counter.html:11` uses `{{ .Permalink | jsonify }}` in JavaScript context. In the production page `/theology-outline/`, Hugo emits:

```js
const t='"https://joshuapsteele.com/theology-outline/"'
```

Those inner quotation marks become part of the `target` query parameter. The conversation display instead reads the canonical link, so the two components can disagree. `reply_context.html` uses the same `jsonify` pattern for its fetch URL and should be corrected and checked alongside it. This establishes incorrect generated requests; live API behavior was not tested.

Use Hugo's context-aware JavaScript serialization of the original string and assert the resulting runtime value. Consolidate the counter and conversation display around one shared fetch/normalization result: both currently call Webmention.io and Micro.blog separately, and their deduplication implementations differ. Their source templates contain approximately 22 KB combined, repeated inline on applicable pages; a fingerprinted shared asset would also allow cross-page browser caching.

## 3. Medium: remove redundant head output and unnecessary downloads

`layouts/partials/extend_head.html` duplicates work already done by PaperMod's `head.html`:

- PaperMod bundles `css/extended/*.css` into its main stylesheet; the override loads `custom.css` again as a separate stylesheet. Confirmed two stylesheet links in production output.
- Open Graph and Twitter metadata are emitted by both `extend_head.html` and the theme's metadata partials. The production scan found duplicated core social tags on 684 HTML pages. For example, the theology outline page has two different `og:title` values. Keep one authoritative implementation, preserving the intended fallback image and cover behavior.
- Every page preloads `/images/default-social.png`, a **2,195,665-byte** social-card image. A social preview image does not need a page-wide rendering preload. Remove that preload and optimize the image separately if useful.
- Review Google Fonts preconnects and other connection hints against resources actually used.

These are source/output-confirmed inefficiencies; no measured network timing improvement is claimed.

## 4. Medium: add validation before deployment and improve publication ordering

`.github/workflows/hugo.yml` has push, schedule, and manual triggers, but no pull-request validation. Add a separate read-only PR workflow for production build, disclosure checks, rendered links, and feed parsing; it should neither deploy nor send Webmentions.

`scripts/deploy.sh` blindly stages everything, commits, pushes `origin main`, and prints success without fail-fast handling, build verification, or a current-branch check. From another branch it can commit there while pushing local `main`. Replace this with an explicit checked deployment workflow or retire the wrapper in favor of reviewed commits/PRs.

Two workflow risks warrant targeted work:

- Webmentions are sent in the build job **before** Pages deployment. A recipient may fetch a source URL that has not gone live yet. Send after a successful deployment, with retry/idempotency behavior.
- Deployment-only concurrency serializes deployment but does not establish commit freshness. An older, slower build can become deployable after a newer build. Check that an artifact's source revision is still eligible immediately before deployment. The scheduled gate also commits a new revision while the build checks out the triggering revision and refetches remote data; make the intended source/data snapshot explicit.

These are code-path risks, not claims that an out-of-order deployment occurred during this audit. Keep the useful existing “skip unchanged syndication” gate.

## 5. Medium: align Hugo versions and track configuration compatibility

Local 0.167.0 warns that `imaging.quality` is deprecated; CI pins 0.160.1. Decide the supported version, align local setup and CI, and migrate to per-format image quality settings supported by that version. Use the emitted warning as the immediate evidence; do not silently change settings only tested against a different version.

The build produces zero processed images. Changing Hugo image quality will not optimize files simply copied from `static/`; image optimization requires a deliberate asset workflow.

## 6. Medium/low: keep templates maintainable and attribution accurate

- `layouts/_default/single.html` has an unmatched `</div>` immediately after the post-tags list inside the footer. Remove it and validate representative rendered HTML.
- `layouts/partials/post_meta.html` labels the front-matter author but always links that author's h-card to Josh's homepage. Guest authors include Emily McGowin, Hannah King, and others. Introduce an explicit author URL or omit the incorrect link for guests; review feed author attribution too, since the general JSON feed uses the site author.
- `assets/css/extended/custom.css` is 1,460 lines. Split along existing feature boundaries (notes, conversations, profile, shortcodes) only where it helps editing, retaining predictable cascade order. PaperMod already collects extended CSS files.
- A production scan found 50 rendered image occurrences without an `alt` attribute; repeated list/feed contexts mean this is not 50 unique images. Triage the source images and add descriptive or deliberately empty alt text as appropriate. This is not a complete accessibility audit.

## 7. Low: finish small taxonomy and repository hygiene work

The category vocabulary in guidance lists eight canonical categories, but the current audit finds `diy` on `fathers-day-gift-ideas-2026.md` and `Church` on the draft `how-to-lead-a-bible-study.md`. That draft also introduces `James`, `bible study`, and `small groups`. Decide whether `diy` is an intentional addition and document it; normalize the draft vocabulary before publication. Do not mass-consolidate singleton tags just to improve a count.

`.hugo_build.lock` is tracked despite its ignore rule. Stop tracking that generated lock. Review whether `.obsidian/workspace.json` and vendored Obsidian plugin bundles belong in the website repository; preserve intentional shared editor configuration.

Some maintenance scripts import third-party `frontmatter`, but there is no requirements/pyproject manifest. Document/pin dependencies for those optional scripts; retain the useful standard-library-only audit/build checks. Replace the placeholder failing `npm test` with an honest verification entry point once checks are assembled.

Keep `sequoia-cli`: it has a corresponding `sequoia.json`, front-matter identities, and discovery templates. It is not an unused dependency merely because the Hugo build does not invoke it.

- 110 files have source references.

Source-orphan status does not establish that a public URL is unused externally. Review candidates individually, preserving known inbound URLs. The old `cleanup_images.sh` still targets the entire WordPress directory; retiring it is preferable to keeping an executable trap with documentation warnings.

The largest current assets are PDF manuals (about 21.2 MB and 6.8 MB). They cost storage/download size when requested, not an automatic page-load penalty. `.git` still retains historic large media. A history rewrite would affect clones and references; its disruption is not justified merely by the current fast local build. Measure checkout costs before deciding.

## Suggested order

1. Correct published links and JavaScript URL encoding; add focused regression checks.
2. Remove the redundant CSS/metadata/image preload; verify representative pages and social previews.
3. Add read-only PR validation, harden deployment, and align Hugo versions.
4. Archive old reports, simplify maintenance documentation, and address small taxonomy/HTML/author issues.
5. Only then consider optional media pruning and broader CSS/script organization.
